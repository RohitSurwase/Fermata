# Building Fermata Media Player on Windows

## Prerequisites

| Tool | Version | Notes |
|---|---|---|
| **Java** | 17+ | JDK 21 tested |
| **Android SDK** | API 36 | Compile SDK 36, Build-tools 36+ |
| **Android NDK** | 29.0.14206865 | Needed for whisper native module |
| **CMake** | 4.3.1 | Installed on system PATH (`winget install CMake` or manual) |
| **Gradle** | 9.5.1 | Handled by wrapper (`gradlew.bat`) |

## Environment Setup

### Android SDK
Set in `local.properties`:
```properties
sdk.dir=C\:/MyApps/Android/Sdk
```

Or via environment variable:
```powershell
$env:ANDROID_SDK_ROOT = "C:\MyApps\Android\Sdk"
```

## Keystore Setup

### For development / testing (auto-generated)
A debug keystore is auto-generated by `settings.gradle` on first build:
- Path: `res/fermata.jks`
- Alias: `fermata`
- Password: `fermata`

### For your own keystore (Play Store publishing)
Create your keystore (e.g. via Android Studio: Build → Generate Signed Bundle/APK, or using `keytool`).

Then edit `local.properties` to add your credentials:
```properties
sdk.dir=C\:/MyApps/Android/Sdk
storeFile=D\:/path/to/your-release-key.jks
storePassword=your_store_password
keyAlias=your_key_alias
keyPassword=your_key_password
```

The settings.gradle will detect that `storeFile` exists and skip auto-generation.

## Package ID

The base application ID is defined in `fermata/build.gradle`:
```groovy
defaultConfig { applicationId project.getProperties().getOrDefault('APP_ID', 'me.aap.fermata') }
```

The auto flavor adds a suffix:
```groovy
auto { applicationIdSuffix '.auto' + project.getProperties().getOrDefault('APP_ID_SFX', '') }
```

### How the flags change package IDs

| `-PAPP_ID` | `-PAPP_ID_SFX` | Mobile package | Auto package |
|---|---|---|---|---|
| *(not set)* | *(not set)* | `me.aap.fermata` | `me.aap.fermata.auto` |
| *(not set)* | `.myname` | `me.aap.fermata` | `me.aap.fermata.auto.myname` |
| `me.aap.fermata.myname` | *(not set)* | `me.aap.fermata.myname` | `me.aap.fermata.myname.auto` |
| `me.aap.fermata.myname` | `.suffix` | `me.aap.fermata.myname` | `me.aap.fermata.myname.auto.suffix` |

### Example (your setup)

To publish the auto flavor as `me.aap.fermata.auto.myname`:
```powershell
.\gradlew.bat bundleAutoRelease "-PAPP_ID_SFX=.myname"
```

This keeps the base ID same `me.aap.fermata` and the auto flavor adds `.auto` → `me.aap.fermata.auto.myname`.

### Other commands

```powershell
# Clean build
.\gradlew.bat clean

# AAB (auto flavor — runs on both phone and Android Auto)
.\gradlew.bat bundleAutoRelease "-PAPP_ID_SFX=.myname"

# Universal APKs (arm64, armv7, x86_64, x86)
.\gradlew.bat assembleAutoRelease "-PAPP_ID_SFX=.myname"

# Mobile only (no Android Auto)
.\gradlew.bat bundleMobileRelease
```

### Google Services

This app can use Google services for:
- **Google Drive** module (VFS provider)
- Firebase analytics / crash reporting

These require a `fermata/google-services.json` file from a Firebase project. **If you don't have this file** (which is the normal case for fork builds), Google Services are **automatically disabled** — the `gdrive` module is excluded and no Firebase features are compiled. No action needed.

You only need `$env:NO_GS = "true"` if you **do** have `google-services.json` but want to temporarily skip it.

## Changes vs Upstream (Windows-specific fixes)

### 1. `fermata/build.gradle` — Bundle config & minification

**Problem**: On Windows, dynamic feature modules could lose native libraries at bundle time, and ProGuard could strip classes accessed by addon modules via reflection (`Class.forName`).

**Fix**:
- `bundle { abi { enableSplit = false } }` — keeps all native libs in the base APK
- `minifyEnabled false` — prevents ProGuard from stripping dynamically-loaded classes accessed via reflection
- `shrinkResources false` — must be `false` because `shrinkResources true` requires `minifyEnabled true`

### 2. `fermata/src/auto/AndroidManifest.xml` — Play Store compliance

**Problem**: Google Play rejects apps that mix Android Auto (phone projection) with Automotive OS (head unit) features. The `CarAppService` intent-filter conflicts with `MediaBrowserService`.

**Fix**:
- Removed `ACCESS_SURFACE` / `NAVIGATION_TEMPLATES` permissions (navigation-only)
- Removed `android.hardware.type.automotive` feature requirement
- Commented out `CarAppService` intent-filter

### 3. `modules/whisper/build.gradle` — CMake version

**Problem**: The upstream specifies CMake 4.1.2, which is not available in the Android SDK or on the system PATH.

**Fix**: Changed `version = '4.1.2'` to `version = '4.3.1'` (matching the system-installed CMake). CMake is backward compatible within major versions.

### 4. `modules/whisper/src/main/cpp/CMakeLists.txt` — Windows native build

**Problem**: The upstream CMakeLists.txt uses Linux-specific NDK paths and enables Vulkan, which doesn't compile on Windows.

**Fix**:
- `GGML_VULKAN OFF` — Vulkan shader compilation is not supported on Windows
- NDK prebuilt paths: `linux-x86_64` → `windows-x86_64`
- Added `.exe` extension to `glslc` binary
- `cmake_minimum_required` → `4.3.1`

## Known Issues

### Addon crashes
If the app crashes when opening Settings, it's usually due to an addon that references a missing class. All addons are included by default (translate, subgen, cast, chat, felex, poi, tv, web, mlkit, opusmt, whisper). Excluding modules from `settings.gradle` is not recommended as it breaks addon expectation.

### Missing Google Services
If `fermata/google-services.json` is absent, Google Services are automatically disabled. The `gdrive` module is excluded. No action needed.

### CMake not found
If CMake is not on PATH, install it via:
```powershell
winget install Kitware.CMake
```
Or download from https://cmake.org/download/
